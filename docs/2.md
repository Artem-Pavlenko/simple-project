INFORMATION Purpose Scope Term Definition

Adventure A game scenario. Includes a specific mat layout, button mappings and a set of Challenges. An Adventure is exported as a single binary file, that may be deployed on an SD card. Challenge A single mini-game within an Adventure. Each Challenge has its own end states, success/failure conditions and feedback effects. Multiple Challenges can be bundled under one Adventure. Pad One of the 12 pressure-sensitive buttons located on the circular mat of the game console. These are the primary interactive elements used by the player during gameplay. Button One of the configuration or control buttons on the physical console (distinct from the Pads). These are used for triggering predefined system behaviors. Button Press The moment the button transitions from an unpressed (up) state to a pressed (down) state. This occurs once per physical press, regardless of how long the button is held. Button Hold The button is currently being held down. This remains true for as long as the button remains pressed. Node A discrete unit in the game’s flowchart editor. It represents a game state or frame, encapsulating parameters such as motor behavior, LED outputs, conditions for node-level success/node-level failure, and user interaction rules. Edge A directional link between two Nodes in the flowchart. It defines the transition from one game state to another based on the outcome of the preceding node (success or failure). Node-Level Success = Success A successful completion of a Node’s expected player interaction — for example, pressing the correct Pad within a time limit. This document aims at defining the functional and non-functional requirements for the Spin&Play No-Code Web-App Interface for the creation of Spin&Play games. It explains the purpose and features of the system, the interfaces of the system, what the system will do, and the constraints under which it must operate. The platform is a web-based tool that allows game designers to create interactive experiences for a specialized hardware console created by CSEM within the JUMPSPINNER project that features 12 multi-color LEDs, a speaker, variable speed motors, and multiple input buttons. The platform enables users to design game logic through a visual interface, and export compatible binary files that can run directly on the target hardware, through the use of na SD card.

Definitions

Node-Level Failure = Failure A deviation from the expected outcome — such as pressing the wrong Pad, or no input received within the allotted time. Challenge-Level Success Indicates that the player has completed the game or objective as intended. Not to be confused with Node-Level Success. Challenge-Level Failure Indicates that the player has failed the objective of the game, triggering the end of the game sequence. End State A final Node in the game flowchart, where no further transitions are possible. This can either be a Game-Level Success or Game-Level Failure Node. Flowchart The graphical representation of the game's logical structure, composed of interconnected Nodes and Edges. It defines the full sequence of possible gameplay states and transitions. Start State An initial Node in a game’s flowchart. It defines the very first set of instructions or conditions presented to the player when the game begins. Transition Condition The rule or event that determines whether the game should move from one Node to another. Conditions include input validation, timeouts, specific button presses or rod hits. User Any individual interacting with the web application. Users are responsible for creating, editing, managing, compiling or exporting games via the platform. Player Any individual interacting with the game console. Editor The game design interface within the application where Users construct the sequence of game states (Nodes) and transitions (Edges) System The complete software and cloud-based infrastructure described in this document. Binary A compiled firmware-compatible file representing a complete Adventure, including all linked challenges and its assets. It is intended for flashing on an SD card for execution by the device's firmware. Challenge Selection Mode A firmware-driven interface where players can select a challenge by pressing a valid combination of physical buttons before gameplay begins Waiting Mode A paused game condition where the system awaits player interaction while displaying a distinctive light-blue breathing LED pattern to signal input is required. Note: the visual waiting indicator may vary depending on firmware specifications.
